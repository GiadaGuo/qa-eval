- `configs/semantics/v1.0.0.json` 保存通用文档和政策语义，复用 `document.title`、`document.body.html`、`document.body.plain`。类型、表示和基数由语义定义描述，必填和非空约束仍来自 Calculator Input Contract。自定义语义可登记和查询，键使用 `custom.` 前缀，同一数据集中唯一，同一数据集不同版本可见。
- `mapping_revision_service.py` 用现有模板匹配已发布 Schema，返回字段、模板版本、匹配分数及逐项依据。推荐初始均待确认。码表、日期单位和含义、发布主体及文号优先级、附件配对继续待业务确认。
- 增量迁移 `7d3f74b8e129` 在 `datasets` 持久化自定义语义，在 `dataset_versions` 持久化草稿和默认摘要。正式修订继续写入 `mapping_revisions`。草稿操作以数据库事务串行更新同一版本。
- `apps/api/routes/dataset_versions.py` 接入工作流。`input_resolver.py` 校验已冻结的 Transform 摘要。`evaluation_run_service.py` 在新 Run 未指定摘要时读取默认修订，显式摘要优先，已创建 Run 继续使用既有 FrozenInputPlan。

## M2 API

以下 M1 路径相对于 `/api/v1/dataset-versions/{version_id}/mapping`。工作流用于已发布的 v3 版本。

| 方法与路径 | 请求 | 响应及状态 |
|---|---|---|
| GET `/semantics` | 无 | 200，语义定义数组。字段为 `key/version/name/description/type/representation/cardinality`。 |
| POST `/semantics` | 一个语义定义 | 201，已登记定义。非 `custom.` 键或同数据集重名返回 422。 |
| GET `/recommendations` | 无 | 200，`schema_fingerprint, fields, provenance, items`。模板未匹配时 `provenance=null`、`items=[]`。 |
| GET `/draft` | 无 | 200，`schema_fingerprint, base_digest, items, default_digest`；初始草稿为空。 |
| PUT `/draft` | `{"items":[...]}` 或 `{"from_digest":"sha256:…"}` | 200，保存后的草稿。items 是完整替换，省略旧项即删除。已确认绑定保持原内容时保留确认，绑定内容更新后恢复待确认。请求中的 confirmed 不用于设置确认。基于历史摘要派生需要逐条重新确认。 |
| PUT `/draft/confirmation` | `{"semantic":"document.title","representation":"text/plain","confirmed":true}` | 200，更新后的草稿。用 `false` 撤销确认。复合键为语义和表示。 |
| POST `/preview` | `{"sample_id":"…","digest":"sha256:…","slots":[]}` | 200，`digest, sample_id, record, values`。省略 digest 预览当前草稿（包括待确认项）；指定 digest 则固定读取该修订。 |
| POST `/publish` | `{"make_default":true}` | 201，`digest, revision, default_digest`。只发布已确认绑定，确认集为空时返回 422。默认情况下只发布修订。 |
| PUT `/default` | `{"digest":"sha256:…"}` 或 `{"digest":null}` | 200，`default_digest`。仅接受本版本已发布修订或清空。 |

修订列表和详情继续使用 `GET /api/v1/dataset-versions/{version_id}/mapping-revisions?limit=20&offset=0` 和 `GET /api/v1/dataset-versions/{version_id}/mapping-revisions/{digest}`。已有整包确认 POST 保留 P2 调用兼容。M2 使用草稿确认与发布路由，以确保只发布逐条确认的绑定。未知版本、样本、修订或草稿项返回 404，请求和业务验证错误返回 422。

保存派生正文绑定的最小请求如下。直接映射省略 `source_representation` 和 `transform`。同一物理字段可绑定多个语义。

```json
{
  "items": [
    {
      "semantic_version": "1.0.0",
      "binding": {
        "semantic": "document.body.plain",
        "field_tokens": ["content"],
        "representation": "text/plain",
        "source_representation": "text/html",
        "transform": "html_to_plain@1.0.0"
      }
    }
  ]
}
```

预览默认按 `semantic:representation` 命名输出，`slots` 也可传入正式 InputSlot 形状并按 `name` 取值。为观察缺少绑定，预览将槽视为可选并返回 UNBOUND，正式评测预检仍拒绝缺少必填绑定。每项包含 `raw_value, value, field_tokens, semantic, representation, source_representation, status, diagnostics, origin`。状态沿用 Resolver 的 UNBOUND、MISSING、NULL、EMPTY、PRESENT、INVALID_TYPE、INVALID_CARDINALITY 和 TRANSFORM_FAILED。失败状态的 diagnostics 返回对应状态码。存在值的 origin 提供原件摘要、字节起点、字段路径、转换标识及摘要。顶层 record 保留原始 v3 信封及 JSON 类型；API 测试以十进制解析验证原始值与解析值的高精度数字保真。

## S0 真实验收与恢复

- 数据版本 `01a21137-724b-7691-8a60-4fa110654627`；运行目录 `data/runtime/policy-s0/`；数据库 `platform.sqlite3`。S0 的数据库由 ORM 初始化而无 Alembic 标记，备份后标记为 `238dc116e65c` 并应用增量迁移。迁移前隔离库副本位置为 `/tmp/qa-m1-policy-s0-before.sqlite3`。
- 样本 `36cc81a5-f97a-5856-84bc-67afe4ac36f7`。模板推荐返回 39 个字段，先从旧修订派生草稿，再保存推荐草稿。预览记录与样本接口返回一致，title 和 HTML 原值逐字符一致，由同一 Transform 生成的纯文本为 210 字符。额外未绑定槽返回 UNBOUND。定向夹具覆盖实际缺键、NULL、EMPTY、INVALID_TYPE 和转换失败。
- 仅确认标题、原始 HTML 正文、派生纯文本三个绑定。保存修改后的标题路径使确认失效；重新确认后可重发相同摘要。其余 13 项保持待确认。
- 旧修订 `sha256:2045c24d7af7010e0d6b3dd543b5ceca7eeb93afc5eef9c26b39dbc782db90bf`；新修订 `sha256:d9e0e502b1b42914c03b290a913c59271c663adb0ec9e583dbdfff095d171521`。将默认指针临时指向旧修订后重建应用和数据库连接，两份修订仍可按指定摘要解析，派生值和来源一致。最终默认指针指向新修订。
- 下游 `text_completeness@1.1.0` 小样本集成测试在创建 Run 后切换默认指针。旧 Run 继续使用冻结的输入，结果与基线一致。真实 S0 只执行 API 点查和解析，未创建评测 Run，也未扫描或复制 5.9 GB 原件。
