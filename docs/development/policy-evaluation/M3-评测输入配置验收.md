## 契约与预检

- `POST /api/v1/quality-contract-versions/input-preflight` 接受数据版本、指标和算子的键及版本、参数、可选 `mapping_digest` 和按槽名组织的 `input_selectors`。返回 `status`、可用的 `slots`、阻塞说明 `detail`，v3 就绪时返回冻结计划 `plan`。
- 固定槽从指定或默认修订按 semantic 和 representation 解析。显式可配置槽可接受 `{"field_tokens":["title"]}` 或 `{"semantic":"document.title"}`。必需槽无选择器或映射即阻塞；可选槽可以 UNBOUND。直接原始字段选择无需映射修订。M3 未增设生产动态槽。
- 状态包括 READY、MAPPING_MISSING、FIELD_NOT_SELECTED、FIELD_NOT_FOUND、INPUT_INCOMPATIBLE、ARTIFACT_MISSING、CONTEXT_MISSING、CONTRACT_NOT_MIGRATED、NOT_APPLICABLE、DISABLED 和 INVALID_CONFIGURATION。预检检查 Registry、适用性、参数及已登记 Schema；不扫描记录。逐记录的 MISSING、NULL、EMPTY 等由 Worker 使用冻结计划解析，配置阻塞不计入质量缺陷。
- 现有契约发布请求支持 `mapping_digest` 与 `input_selectors`，随 `calculation.implementation_constraints.attributes` 保存。Builder 发布时保存实际通过预检的摘要。旧契约仍可在创建 Run 时选择修订。计划冻结数据版本、原件身份、绑定及选择器、实现和转换摘要、参数。历史 Run 执行读取自身计划。
- 当前 v3 可运行的生产输入是 RAW_RECORDS。独立逻辑工件及 v3 共享推理仍待适配。Schema 兼容检查使用已登记的顶层物理类型；嵌套路径和部分记录的类型差异由 Resolver 判断。v2 的参数、阈值和既有发布路径沿用原实现。

## 验收

- S0 数据版本 `01a21137-724b-7691-8a60-4fa110654627`。真实浏览器从指标库选择 `02080104 / text_completeness@1.1.0`，显示默认修订，切换到旧修订 `sha256:2045c24d7af7010e0d6b3dd543b5ceca7eeb93afc5eef9c26b39dbc782db90bf`，正文槽显示 `content → html_to_plain@1.0.0`，预检 READY。保存 S0 验收契约 `01a21189-f852-7c64-b71f-f12dfafba556`，重进页面按 ID 回读同一摘要。S0 未启动 Run，也未扫描或复制原件。
- 小样本真实 Run 使用隔离的既有 v3 JSONL 集成夹具，经正式 Quality Contract、Planner、Worker 和 Resolver 执行 `text_completeness@1.1.0`。创建 Run 后改默认映射仍得到原冻结输入结果；v2 对照输出一致。动态字段使用测试内 Registry 描述符变体，验证选择器保存、回读、冻结及执行，同步验证 Resolver 读取原始字段。
- API 回归覆盖缺少映射或必需绑定、原件不可用、v2 算子未迁移、数字字段与字符串槽不兼容。定向后端 **5 通过**，前端 **21 通过**，TypeScript、生产 build 和生成 Schema 同步检查通过。Vite 有现有的大分包提示。

## 建议测试顺序

1. 先复验 `02080104 / text_completeness@1.1.0` 的固定正文槽。
2. 在测试夹具复验原始字段及语义选择器、必需槽和历史冻结。
3. 后续迁移优先验证使用现有正文绑定的本地确定性算子，再处理需要字段关系、码表或日期语义的政策算子。
4. 标注、词典、模型和独立工件依赖按矩阵补齐后再验证。禁用项和占位项维持 Registry 原状态。
