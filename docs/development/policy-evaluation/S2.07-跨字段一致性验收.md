# S2.07 跨字段一致性验收

## 阻断根因与改动

0207 的 Registry 绑定使用原生统计输出，逻辑输入契约声明 `DIRECT`。构建器原先按原生绑定是否配置主度量来判断能否进入 v3 发布。现在按逻辑输入的执行模式判断，并继续走原生契约发布。发布接口为 0207 v3 重新执行预检，校验 Registry 参数结构、关系图和 matcher 资源，并使用 Resolver 检查发布版本、映射修订、字段来源、重复边及字段类型。

0207 通过 Registry 选择评测输入编辑器，沿用 0201、0202 的构建页。关系由用户逐组选择和确认，可选目标版本的真实字段或已确认映射中的语义。精确和结构化匹配要求明确两侧共同表达的业务属性。编辑器生成 `fields`、`relations` 和 `InputSelector`，关系默认权重 1、非必评、无否决。正式评测与仅观察均使用冻结的映射及选择器。已发布页面回显主度量、门禁、输入和关系，完整参数可展开。

## 判定口径

- `confirmed_consistent_record_ratio` = 标签 1 记录数 ÷ 全部输入记录数。分母包含未判定记录，空分母返回空值。总体门禁默认 GTE 90%，90% 为配置建议。
- 记录级最低覆盖率默认 60%，通过分数默认 80%。覆盖率为可评分权重除以适用权重，分数为可评分关系的加权平均。
- 确认冲突且该关系启用否决时标记 0。随后依次检查无适用关系、必评未知、无可评分关系和覆盖不足，均标记未判定。剩余记录的分数达到阈值时标记 1，否则标记 0。
- 方法参数从 Registry schema 读取。语义与类别匹配需要经版本化的资源和阈值，界面提示缺项并支持加载已有资源文件。校准曲线按 schema 选用。

- Run `01a21ba3-33c5-74f0-aa35-f2787c0a42f1`，报告 `01a21ba3-33dd-7cf5-a5ee-9f4cb1b289d8`，证据 `802ed75c-e236-513b-b4c8-ae99dabebbce`。将同一配置的总体门禁设为 GTE 6.25% 时，边界 Run `01a21bb7-8563-7886-9535-d0c79527484e` 的报告判为 PASS。
- API 验证同源字段预检拒绝、同源配置直接发布返回 422、缺少语义匹配资源时预检拒绝。同源 API 用例包括自环。现有单测覆盖重复边、类型不兼容、记录判定阈值相等、必评未知、覆盖不足、记录级同源和否决优先级。
- 实际浏览器从指标管理完成 0207 配置（默认权重 1、总体 90%、最低覆盖 60%、记录通过 80%）、预检、发布、按 ID 读取、正式 Run、证据预览及报告读取。浏览器契约 `01a21bb8-b0d7-75d0-bda8-d407c14ee277`，Run `01a21bb9-8efa-7a1d-b42b-cd8a90029b71`，报告 `01a21bb9-8f20-7085-96e1-4637f1cb1502`。报告显示分子 1、分母 16，90% 门禁未通过。

## 2.2.0 Embedding 实现补记

新版使用同一 v3 Resolver、原生超阈判定与报告链路。历史 2.1.0 的执行代码、绑定身份和已发布契约可继续读取和运行。新版 UI 默认选用 Embedding，并把历史 TF-IDF 方法显示为文本相关性匹配。TF-IDF 选择平台版本 `policy-reference-128-v1`，发布时冻结资源快照与试运行阈值版本。

平台复用 0206 的本地 BGE 编码器和 SQLite 内容哈希缓存。API 与 Worker 可通过现有 `QA_EVAL_0206_BGE_MODEL_DIR` 配置相同的离线 checkpoint，并通过 `QA_EVAL_0206_EMBEDDING_CACHE` 共享缓存。缓存应位于模型目录之外。未配置共享缓存时，每个 Run 有独立缓存。契约冻结 checkpoint 指纹和运行依赖版本、分块策略、聚合与阈值。当前验收环境无本地 BGE checkpoint，也未安装对应模型依赖。

Embedding 默认使用最高分块余弦，适用于短文本与长正文的局部相关性。双向最佳匹配均值可衡量两侧整体覆盖。每段按模型 token 上限再次切分，向量批次上限 32，同一进程一次只执行一个编码窗口。默认每段 320 字符、每字段 64 段，超出上限返回未知。余弦判定分数下限为 0，默认低于 0.45 判不一致，达到 0.72 判一致，中间为未知。上述阈值未经业务校准。

Decision 保存比较字段来源、匹配分数、阈值及两侧最高匹配片段，每段摘录最多 160 个 Unicode 码点。直接原文可按工件和文本哈希验证位置。经过变换的字段使用解析值坐标和摘录。原文高亮只用于可验证原文坐标。

- 浏览器验证 2.2.0 默认方法、试运行阈值、本地 BGE 未配置提示，以及选择平台 TF-IDF 资源后字段预检 READY。
- 真实 policy v3 的 16 条小样本，经标题与已确认纯文本正文映射完成 TF-IDF 正式 Run。结果为一致 8、不一致 2、阈值区间未判定 6，总体一致率 50%。Run `01a21bd4-a808-739e-b55f-3aede043f325`，报告 `01a21bd4-a835-71c0-a603-d9c7c013baca`，证据 `95243c55-8889-514e-8344-a416bb306b9d`。
- 本地可控测试 Provider 经真实 Resolver、Planner、Worker 与 Report 验证相似和不相关文本、长正文尾部、缺值、编码失败、冻结模型身份变化、跨 Run 缓存复用和原文位置校验。实际 BGE checkpoint 的推理与业务校准待平台配置资源后验收。
