# 政务数据知识图谱与高质量数据集建设方案

> **项目**：浙江省政协"人工智能+政协履职"项目 · 政协 AI 专属知识库
> **应用场景**：公文写作、提案撰写、 智能中枢（检索）
> **治理平台**：息壤高质量数据集平台（数据治理中心 / 数据标注中心 / 数据应用中心）
> **编制依据**：《0827浙江省政协"人工智能+政协履职"项目可行性研究报告v4.8.4》
> **质量坐标**：《高质量数据集 质量评测规范》（SAC/TC 609）、《面向人工智能的数据集质量通用评估方法 总体要求》（T/CCSA 413-2023）
> **版本日期**：2026-10-25

## 1 建设大纲与标准化流程

### 1.1 建设对象

- **高质量政策数据集**：政策原文、条款、关系、场景样本四类数据，按国家标准评测合格。
- **政策知识图谱**：把数据集中的政策、条款、知识块及其关系组织为可查询、可推理、可溯源的图。

两者关系：**数据集是原料，图谱是语义组织；共用同一套字段、同一套标签、同一套规则。**

### 1.2 标准化流程

按国标数据集建设流程组织：

`数据需求 → 数据规划 → 数据采集 → 数据预处理 → 数据标注 → 模型验证`

| 阶段 | 主要工作 | 关键产出 | 标准锚点 |
|---|---|---|---|
| 数据需求 | 三个场景需求拆解；确定数据范围、规模、时效与质量目标 | 需求清单 + 数据指标 | 应用说明完整性 0104；内容多样性 0301 |
| 数据规划 | 来源清单、字段模型、本体、规则体系、标注体系与版本控制设计 | 字段模型、规则卡、本体、标注规范 | 建设过程完整性 0103 |
| 数据采集 | 来源白名单、原文快照、元数据登记 | 原始语料 + 快照 URI + 哈希 | 建设过程完整性 0103；内容真实性 0205 |
| 数据预处理 | 去噪去重、版式归一、编码统一、条款切分；执行治理规则与质量评估 | 纯文本库、条款库、质量评分卡 | 格式规范性 0201、结构完整性 0204、内容干净性 0208 |
| 数据标注 | 四层标注（文档 / 条款 / 关系 / 场景）、质检、金标固化 | 标注数据集 + 数据集卡 | 标注规范性 0203、标注准确性 0304、内容特征完整性 0102 |
| 模型验证 | 用数据集训练与评测模型；验证图谱查询服务；效果回流 | 模型评测报告、图谱质量报告、回流清单 | 规模完整性 0302、内容时效性 0303、模型适配性 0305 |

> **治理、质量评估与图谱构建的落位**：治理规则在「数据规划」建卡、「数据预处理」执行；质量评估在「数据预处理」做数据质量评测、在「模型验证」做模型应用评测；知识图谱不单列阶段——本体在「数据规划」定义，节点与关系在「数据标注」产出，服务效果在「模型验证」验收。

### 1.3 双环反馈机制

标准化流程不是单向流水线。反馈分两环：**快环**保证本批数据不出错，**慢环**保证下一轮数据不缺项。

```
              ┌───────── 慢环：能力盲区 → 数据盘点与规划 ─────────┐
              ↓                                                   │
数据需求 → 数据规划 → 数据采集 → 数据预处理 → 数据标注 → 模型验证 ─┘
                                    ↑  │
                                    │  ↓
                              质量评估（快环）
                          不达标 → 清洗 / 治理调整
```

| 环路 | 触发条件 | 反馈路径 | 处理动作 | 闭环标准 |
|---|---|---|---|---|
| **快环**（阶段内） | 质量评分卡任一指标低于阈值；规则误报超阈值；同类缺陷聚簇 | 质量评估 → 清洗 / 治理规则 | 生成问题簇与规则变更单 → 只重跑受影响批次 → 复评 | 复评达标或豁免经审批；规则变更留版本 |
| **慢环**（端到端） | 模型验证中某场景 / 某类条款指标不达标；错误聚簇指向数据盲区 | 模型验证 → 数据盘点 → 数据需求 / 规划 | 错误归因（数据缺口 / 标注错误 / 模型能力）→ 更新缺口清单 → 调整采集与标注策略 → 进入下一轮 | 缺口进入下轮计划并有交付物承接；盲区复测通过 |

## 2 执行总览

### 2.1 三个场景对数据的要求

| 应用场景 | 典型问题 | 数据侧必须做到 | 图谱侧必须提供 |
|---|---|---|---|
| **公文写作** | 该引哪几条政策？这些表述过时了吗？ | 现行有效、条款级可定位、表述不过时、引用可溯源 | 主题→条款→政策 2 跳子图 + 证据句 |
| **提案撰写** | 建议与现行政策冲突吗？以前提过吗？该谁办？ | 冲突前置拦截、年度重复区分、责任主体明确、立案口径统一 | 提案→政策冲突子图 + 职责依据链 |
| **政策关联** | 新规和哪条旧规冲突？这两段是不是一回事？ | 引用 / 修订 / 废止 / 上下位关系正确、块级关系可判、冲突可检出 | 政策 / 条款 2–3 跳子图 + 关系类型 + 置信度 |

## 3 数据治理方案

标准依据：TC609 共 17 项指标（说明文档 4、数据质量 8、模型应用 5），三个维度分别计分且均需 ≥90 分；T/CCSA 413-2023 共 12 项一级指标、36 项二级指标、5 个质量等级，分数据基础质量与数据应用质量两段。本章把「治理」拆成两件可执行的事：**评测发现问题，治理修复问题**。任一规则未配置治理动作、或治理后未复评，均视为未闭环。

### 3.1 四层评测框架

息壤平台「数据治理中心 › 模型管理 › 模型配置 › 规则库」预置 10 条规则：模型应用、内容干净性、类型一致性、内容一致性、内容真实性、结构完整性、标注规范性、安全规范性、格式规范性、说明文档，均为**单记录字段级**评测。评测按「能不能进、合不合规、够不够用、好不好用」四层组织：前两层是底线与通用语义，后两层分别面向单一场景与模型效果。

| 层级 | 定位 | 条数 | 数据对象 | 主要粒度 | 命名示例 | 平台能力使用策略 |
|---|---|---|---|---|---|---|
| 第一层 基础质量门禁评测（BG） | 全场景强制，任一不通过不得进入标注与图谱 | 7 | R / P / O | 字段、文档、块、数据集 | BG-01 说明文档评测 | 平台能力全部具备，直接使用，补齐跨记录底线 |
| 第二层 政务通用评测（TY） | 三个场景共用的政策语义判定 | 10 | R / P / O | 文档、条款、块、关系对 | TY-01 政策身份一致性评测 | TY-03 直接使用，其余政务新建 |
| 第三层 场景增强评测（GW / TZ / GJ） | 单一场景特有、通用规则无法替代的判定 | 7 | R / P / O | 片段、样本、政策对 | GW-01 写作素材可引用性评测 | 平台不具备，政务侧新建，优先设计可复用能力 |
| 第四层 模型应用评测（MA） | 数据集在三个场景模型上的实际效果 | 5 | O | 样本、数据集 | MA-01 内容分布代表性评测 | MA-04 / MA-05 直接使用，其余政务新建 |

#### 3.1.1 评测数据类型与粒度

**数据类型**：按对象在数据流水线中的位置分三类。多数规则以一类为主对象、另一类为参照集。

| 代号 | 类型 | 定义 | 典型数据 |
|---|---|---|---|
| R | 原始数据 | 采集入库、未经加工的政策原文与来源信息 | 政策原文快照、发文字号、发文机关、发布日期、来源 URI、提案与答复原件 |
| P | 过程数据 | 预处理、标注、图谱构建产生的中间产物 | 清洗纯文本、条款库、知识块、实体表、候选三元组、关系候选集、RAG 检索块与向量索引、标注中间结果 |
| O | 结果数据 | 进入下游使用的成品或模型产出 | 标注成品数据集、数据集卡、图谱库、场景样本集、模型生成结果与评测报告 |

**数据粒度**：粒度决定「判什么」和「结论往哪挂」。同一规则可能跨两级，下表标主粒度，必要时注明聚合级。

| 粒度 | 判定单元 | 典型规则 |
|---|---|---|
| 字段级 | 单条记录的一个或多个字段 | BG-01、BG-05、BG-06、TY-03 |
| 文档级 | 整篇政策 | BG-02、BG-03、TY-02 |
| 条款级 | 条 / 款 / 项 | TY-04、TY-05、TY-08 |
| 块级 | 知识块或句级片段 | BG-03、TY-06、TY-07 |
| 关系对级 | 两条记录、两个条款或两份政策之间 | TY-01、TY-09、TY-10、GJ-01 |
| 数据集级 | 整个数据集或全库统计 | BG-01、BG-03、MA-01、MA-02、MA-03 |
| 样本级 | 场景样本或模型单次输出 | GW-01、MA-04、MA-05 |

#### 3.1.2 评测要素与输入输出约定

评测输入、标注内容与图谱属性共用同一套 7 组要素（G-1～G-7），避免口径分叉。

| 组 | 名称 | 包含内容 |
|---|---|---|
| G-1 | 标识 | 文档、条款、知识块、关系的编号，版本号，来源地址，快照哈希 |
| G-2 | 类型 | 文种、效力层级、地域、功能类型、刚性等级 |
| G-3 | 效力 | 发布日期、生效日期、效力状态、废止或修订依据、版本链 |
| G-4 | 内容 | 标题、文号、条款号、条款路径、原文、清洗文本、知识块文本、原文坐标 |
| G-5 | 指标 | 指标名称、数值、单位、周期、阈值、指标类型 |
| G-6 | 权限 | 密级、敏感类型、可见域、去标识化标记 |
| G-7 | 溯源 | 证据句、来源地址、原文坐标、置信度、命中规则、判定版本 |

**输入约定**：任一评测的输入由三部分组成——**评测对象**（政策原文、条款、知识块、关系、样本或数据集）、**待检内容**（该规则要核验的语义或属性）、**参照依据**（规则库、词典、标签组、金标集、原文快照、候选集）。参照依据必须带版本号，保证评测可复现。

**输出约定**：任一评测的输出由五部分组成——**判定结论**（通过 / 不通过 / 需人工复核）、**问题清单**（问题类型、所在位置、原文或数据片段）、**证据定位**（证据句、来源、坐标）、**治理建议**（治理动作与做法，对应 3.2）、**评测版本**（规则与参照依据版本）。

**闭环要求**

1. **一规则一动作**：每条规则至少配置一条默认治理动作；无治理动作的规则不得上线。
2. **分级处置**：高风险问题阻断下游并在批次交付前闭环；中风险在批次内修复；低风险累积到周批处理。
3. **处置留痕**：治理动作写回判定对象，形成「发现—派单—处置—复评」记录，与 D-G-07 看板打通。
4. **复评强制**：治理后按原规则、原参照集版本复评；复评不通过转 GOV-08 或 GOV-09，禁止直接放行。
5. **慢环承接**：涉及来源、标注规范、规则体系的系统性问题，转入 1.3 慢环，进入下一轮数据规划。

## 4 数据标注方案

标注的目标不是"给文档打标签"，而是为**文档、条款、关系**三种粒度分别建立可计算的描述，再叠加**场景标签**，使标注结果同时支撑质量治理、图谱构建和模型验证。

本方案把标准要求直接纳入标注内容：说明文档要求落为数据集卡，敏感与可见域落为各层必填字段，标注过程元数据贯穿全部层级，应用质量要求落为场景样本与评测元数据，分布与代表性要求落为数据集级统计。标注结果与治理共用字段，与图谱共用主键。

| 2. 政策效力层级 | 法律→行政法规→部门规章 / 地方性法规→地方政府规章→规范性文件→工作通知 / 指导性意见；另标上位法依据、本级文件、基层落实文件 | 构建上下位关系；判断提案是否符合上位政策框架 |
| 3. 管辖地域层级 | 国家级、跨省、省级、地市、区县、园区 / 专项功能区；是否仅适用于特定试点区域 | 写地方提案、区域公文时筛选适用地政策 |
| 4. 时间生命周期状态 | 有效、部分修订、全文修订、已废止、自动失效、过渡期、暂停实施、拟修订；记录修订 / 废止依据文号 | 防止引用失效政策；追踪政策迭代 |
| 5. 主题领域 | 一级：经济、财税金融、科技创新、产业发展、人才人社、城乡建设、生态环境、公共服务、教育卫生、法治、营商环境、乡村振兴、对外开放；二级、三级细化 | 主题聚类、专题政策包、检索召回 |
| 6. 政策类型（功能属性） | 立法管制、约束监管、扶持激励、补贴扶持、税收政策、审批改革、应急处置、规范流程、试点探索、评估考核 | 快速区分鼓励 / 限制 / 监管 / 保障 |
| 7. 政策力度 / 刚性等级 | 强制、约束性、指导性、参照建议、免责 / 解读 | 判断约束力；评估提案建议可行性 |
| 8. 适用主体对象 | 政府部门、事业单位、国企、民企、小微企业、个体工商户、科研机构、个人、特定群体 | 精准匹配公文与提案对象，避免错配 |
| 9. 特殊属性标记 | 试点政策、自贸区 / 高新区等特殊区域、重大战略配套、应急政策、规范性文件、专项定向政策 | 提案创新点挖掘；专项素材筛选 |
| 10. 敏感与可见域 | 密级（公开 / 内部 / 秘密）、敏感类型、可见域、去标识化标记 | 跨域引用不越权；数据下发前裁剪 |

> 校验规则：TY-01 / TY-02（身份与生命周期）、TY-03（文种、层级、位阶）、BG-06（敏感与可见域）。

### 4.3 第二层：条款 / 段落级标注

颗粒度为条、款、项及重要独立段落（目标、举措、保障、责任、禁止、资金、时限）。条款是图谱的最小语义单元。

| 维度 | 标注内容 | 业务价值 |
|---|---|---|
| 1. 语义功能块 | 总则、发展目标 / 指标、重点任务 / 举措、支持政策、禁止 / 限制、责任分工、审批流程、时限要求、监督检查、争议条款、法律责任、附则、术语定义 | 直接读取目标段、举措段、保障措施模板 |
| 2. 政策工具类型 | 供给型（投入、基建、平台、人才、科研）、环境型（税收、补贴、准入放松）、需求型（采购、示范、推广、试点）、规制型（产权保护、禁令、处罚、审批） | 检索同类政策工具组合 |
| 3. 实体抽取 | 组织机构、专项 / 基金名称、证照 / 资质、项目类型、指标数值、专有名词、法定概念 | 抽取责任主体与量化指标 |
| 4. 权利 / 义务 / 约束 | 赋权、义务、禁止、许可、豁免、鼓励 | 风险审查；判断是否突破上位许可边界 |
| 5. 关键指标与阈值 | 数值、比例、金额、年限、时限、门槛条件；区分约束性 / 预期性指标 | 提案测算、公文目标设定、政策比对 |
| 6. 术语与定义链接 | 政策内专有名词链接术语词典；跨政策同一概念唯一映射 | 解决同物异名、同名异物 |
| 7. 效力要素 | 约束强度、适用条件、例外 / 但书、时限、触发条件、法律效果、依据引用 | 冲突检测（尤其例外型）的结构输入 |
| 8. 敏感与证据 | 敏感类型、密级、可见域、证据句、原文坐标、置信度 | 块级关系证据；越权控制；结论可核验 |

> 校验规则：BG-02（切分与路径）、TY-04（依据要素与权利义务）、TY-05（指标口径）、TY-06（规范表述）。

### 4.4 第三层：政策关系标注

关系标注最终落成**图谱的边**。每条关系必须标注：关系类型、方向、置信度、证据句、原文坐标、关系说明。

**关系类型清单**

1. **层级从属**：上位依据、下位实施、转发关系、授权制定。
2. **引用与被引用**：直接引用、隐含引用、提取引用（提案与答复中引用现行政策作依据）。
3. **迭代演化**：修订替代（全文 / 部分）、废止替代、接续、试点转正。
4. **配套协同**：配套文件、联动政策、提案与承办答复匹配。
5. **冲突 / 不一致**：直接抵触、新旧冲突、地域差异；标注冲突类型、冲突条款位置、适用优先规则（新法优于旧法、上位优于下位、特别优于一般）。
6. **内部知识间**：细化、限定、例外 / 但书、支撑、援引、等价、冲突。

**关系 → 规则 → 落层**

| 关系组 | 产出规则 | 落层 | 关键约束 |
|---|---|---|---|
| 1. 层级从属 | TY-03 类型一致性 | 文档级边 | 同位阶审慎、位阶相称、下位不得与上位抵触 |
| 2. 引用与被引用 | BG-07 溯源可信性 | 文档级 + 条款级 | 被引文件存在且有效；证据句必须出自被引正文 |
| 3. 迭代演化 | TY-01 / TY-02 身份与效力 | 文档级边 | 区分整体替代与部分替代；沿革链双向闭合 |
| 4. 配套协同 | GJ-01 配套协同 | 文档级边 | 三信号加权；必须给出配套理由 |
| 5. 冲突不一致 | TY-09 + TY-10 冲突与适用优先 | 条款级 / 块级边 | 冲突类型、冲突位置、优先规则三要素齐备 |
| 6. 内部知识间 | TY-07 块级关系 | 知识块级边 | 证据粒度 ≥ 条款级，否则不予通过 |

### 4.5 第四层：场景标注

#### （1）公文写作专项标签

- **素材类型**：指导思想、总体要求、工作目标、主要任务、保障措施、组织领导、督导考核、结语表述、过渡句式、规范表述库。
- **可复用程度**：高频经典表达、专项领域特有表达、通用表达、法律强制表述。
- **风险提示**：敏感表达、需结合本地实际、不能直接照搬、需履行报批程序。
- **文种适用**：请示、通知、函、实施方案、工作方案、工作纪要、工作总结。

#### （2）提案撰写专项标签

- **提案角色**：政策依据素材、现存问题佐证、外地先进经验、可借鉴举措、可行性论证素材、风险提示。
- **提案方向**：立法类、政策类、体制机制改革类、民生保障类、产业扶持类、监督建议类。
- **答复关联**：承办单位、答复意见、采纳情况（采纳 / 部分采纳 / 暂不采纳及理由）。
- **政策缺口**：现有政策空白、政策模糊地带、政策执行难点。

#### （3）场景样本与评测元数据

- **场景覆盖**：所属场景 + 主题 + 文种 + 效力层级，用于多样性统计与场景覆盖核验。
- **样本难度**：易 / 中 / 难，按条款嵌套、冲突隐蔽性、表述复杂度判定，用于分层评测与难度分布分析。
- **数据划分**：训练 / 验证 / 测试 / 金标，保证模型训练与评测隔离。
- **模型反馈**：模型版本、错误类型、归因结论，用于慢环回流与下一轮主动学习。
- **标签来源**：人工 / 模型预标 / 规则推导，用于质量追溯与置信度校准。

### 4.7 标注工艺与质量控制

**标注规范**：每个标签项必须写明定义、判定规则、正反例、边界案例、适用层级与是否必填。规范与标签组同版本发布；规范变更须经试标校准后才能全量执行。

**平台落地**：标注在平台「数据标注中心」执行——标签组管理维护标签枚举，标注任务按层级与批次派单，审核结论回写审核状态与置信度；平台规则库的标注规范性评测读取同一标签组，保证规范、标签、规则同版本。

**工艺选型**：大模型预标注 + 规则校验 + 人工复核 + 主动学习回流。L2 约 625 万条、L3 约 396 万边，纯人工不可行；关系判定错误代价高，纯自动不可靠。

**执行流水线**：规则 / 模型预标注 → 规则自动校验 → 分层人工复核 → 双人盲标一致性检查 → 仲裁与规范修订 → 入库固化 → 主动学习回流。

| 机制               | 做法                                                         | 门槛/要求                               |
|---|---|---|
| 试标校准           | 20 人 × 500 条试标，计算类别间 Kappa                         | ≥ 0.80 才正式标注                       |
| 双标与抽检         | 5% 样本双人盲标；按置信度分层抽检：≥0.95 抽 2%，0.85–0.95 抽 10%，0.70–0.85 抽 40%，<0.70 全量 | 双标单项 Kappa ≥ 0.75；抽检问题当日反馈 |
| 金标回归           | 每轮模型更新后在金标集回归                                   | P@1 下降 > 2% 阻断发布                  |
| 交叉校验与版本绑定 | 已标注数据交叉校验；标签组、规范、预标模型、数据集同版本发布 | 告警闭环率 100%；任一变更可追溯         |
| 人员与回流         | 追踪标注员 Kappa 与错误类型，动态派单；模型不达标先做错误归因，再决定重标、补采或模型优化 | 归因结论进入下一轮主动学习队列          |

**模型反馈处理**：模型验证不达标时，先做错误归因：标注错误则重标并修订规范；数据缺口则补采并扩展标签；模型能力问题进入模型优化，不误改标注。归因结论写入模型反馈，并进入下一轮主动学习队列。

> 标注交付物见 6.1「数据标注」表（D-A-01～D-A-07）；三个场景的验收方式见 6.2。

## 5 知识图谱构建方案

图谱构建建立在治理与标注结果之上：**L1 → 文档节点，L2 → 条款 / 知识块节点，L3 → 边，L4 → 场景标签属性**。只把核心条款入图，一切关系必须带证据。

### 5.1 本体设计

**三条原则**

1. **以条款为最小语义单元**：政策 / 条款 / 知识块三级锚点，块级关系可落到句子。
2. **关系必须可证据化**：每条边携带证据句与原文坐标，无证据不入图。
3. **与标注体系同构**：本体字段直接复用治理的 7 组字段模型，不另建口径。

| 本体层 | 内容 | 说明 |
|---|---|---|
| 概念层 | 9 类实体：政策、条款、知识块、发文机关、主题、政策工具、指标、术语、提案 | 覆盖三个场景所需的最小概念集 |
| 关系层 | 7 组、27 类关系：层级、引用、迭代、配套、冲突、内部知识、归属 | 见 5.3 |
| 属性层 | 7 组字段 G-1～G-7：标识、类型、效力、内容、指标、权限、溯源 | 与治理字段模型一致 |
| 约束层 | 主键唯一、可见域交集、证据必需、版本闭合 | 入图校验规则 |
