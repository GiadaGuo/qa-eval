# BG-06-01 敏感要素双通道识别 Calculator 实现前审计与技术设计

> 状态：设计草案，待评审；本阶段未修改业务代码、Registry 或数据库。  
> 审计日期：2026-11-06  
> 目标 Metric：`0202` 安全规范性  
> 拟新增 Calculator：`sensitive_entity_detection@1.0.0`

## 1. 结论与实施前置

BG-06-01 可以实现为独立的、直接执行的 Dataset 级 Calculator，但**不能直接绑定到当前 `0202@1.0.0` 并输出本任务要求的 measurements**。当前 0202 只声明 `safe_record_ratio`、`safe_record_count`、`unsafe_record_count`、`evaluable_record_count`，语义是内容安全分类；敏感要素命中数、分类统计、受影响文档数、扫描覆盖率和通道状态均未声明。Registry 同步会拒绝 Binding 中未由 Metric Definition 声明的 measurement。

实施前必须先评审并完成以下决策：

1. 新增 `0202@2.0.0`（推荐），保留 `0202@1.0.0` 与现有 `content_safety_compliance@1.0.0` Binding，不覆盖旧定义。新版本新增本设计第 8 节 measurements，并保留“命中不是违规”的中性解释。
2. 为 `0202@2.0.0` 新增 `sensitive_entity_detection@1.0.0` Binding，显式列全 `produced_measurements`。Quality Contract 必须显式选择 calculator key/version；优先级只用于推荐，不替代显式选择。
3. 确认 NER 模型权重的许可证、可再分发范围、固定版本与校验和；在目标 Python 3.12、CPU/GPU 环境完成安装和吞吐基准。当前证据不足，不能承诺生产部署规格或总运行时长。
4. 用政务领域的脱敏/合成标注集完成分类别 precision/recall、窗口边界和误报验收；普通人名、普通地名不得自动成为敏感命中。

若不允许升级 0202，则本 Calculator 只能先注册为 `UNAVAILABLE` 设计占位，不能伪装成现有安全比例 measurements 对外执行。

### 2.1 0202 与 Binding 兼容性

- `0202@1.0.0` 是 Dataset scope，适用模态包含 text，持久化策略为 `AGGREGATE_AND_EVIDENCE`。
- 现有 `content_safety_compliance@1.0.0` 是 `SHARED_INFERENCE` Calculator，扫描 `article.body.plain`，输出内容安全分类相关的四项聚合；它不是 PII/敏感要素识别器。
- 现有 Binding 未填写 `produced_measurements`，属于兼容旧 Binding 的空列表；新 Binding 应显式声明。
- Registry 支持同一 Metric 绑定多个 Calculator；Binding 的复合身份含 metric key/version 与 calculator key/version。Logical Planner 从 Quality Contract 的 implementation constraints 精确查找 Calculator 和 Binding，因此新 Calculator 可与旧 Calculator 并存。
- Calculator descriptor 的 `supported_metrics.metric_version_range` 目前只是声明数据；已审计的 Registry sync/Planner 没有验证 semver range。实现阶段需加覆盖测试，不能只依赖该字符串阻止错绑。
- Planner 会校验 Contract 选择的 measurement 是否位于非空 `produced_measurements` 中；Registry sync 会校验这些 measurement 已由 Metric Definition 声明。

### 2.2 SampleRecordV2 与实际政策映射

`SampleRecordV2` 包含：

- `contents[]`：`content_id`、`modality`、语义 `role`、presence、payload、attributes；同一 sample 内 content_id 强制唯一，但 role 不强制唯一。
- `metadata`：任意 JSON object，没有通用的字段文本语义或逐字段 source map。
- `source`：源 artifact ID、源记录 ID、源行、locator 和 attributes；这些是来源/定位元数据，不应默认作为业务正文扫描。
- `annotations` 与 `lineage`：分别是标注和变换链路，不在本 Calculator 默认扫描范围。

政策模板把同一个原始 `$.content` 同时映射为：

- `article.body.html` / `body-html`，`format=html`、`transform=identity`；
- `article.body.plain` / `body-plain`，`format=plain`、`transform=html_to_complete_plain_text`。

因此两者不能分别计数。建议采用下列扫描与去重规则：

1. 只扫描参数 `content_roles` 明确列出的 PRESENT + text + `InlineTextPayload` 内容。默认：正文逻辑槽位优先 `article.body.html`，缺失时回退 `article.body.plain`；另扫描 `article.title`。不遍历任意 content role。
2. 字段文本通过参数 `metadata_paths` 白名单选择，使用受限 JSON Pointer/点路径读取字符串或字符串数组；默认空列表。禁止递归扫描整个 metadata/source，避免 URL、source ID、审计字段和重复源值造成误报。
3. 每个输入建立逻辑槽位 `logical_field`，如 `body`、`title`、`metadata:/publisher/value`。同一槽位的 HTML/plain 是替代表示，不是两个输入。
4. 内容候选唯一键：`sample_id + logical_field + entity_type + canonical_span_identity`。HTML 以源 HTML spans 为身份；plain/metadata 以 content ID 或 JSON Pointer 加 Unicode code-point `[start,end)` 为身份。
5. 跨字段相同文本不合并；它们是两个真实位置。只有显式声明 `same_source_group` 且位置可证明同源时才跨表示合并，不能仅凭字符串相等去重。

### 3.1 HTML Source Map 复用设计

现有 `_LexicalMapParser` 使用 Python `HTMLParser(convert_charrefs=False)`，将可见文本字符映射到原始 HTML 的 Unicode code-point offset，支持实体引用、多段 `source_html_spans`、DOM path，并对 malformed HTML 降级为 `BLOCK_ONLY`。其位置不是 UTF-8 byte offset。

实施时先做一次兼容性抽取：

- 新建中性的 `qa_eval.calculators._shared.html_text_map`（最终名称待代码评审），包含可见文本与字符到原文 span 的映射，不包含政策结构 schema 或规则。
- `policy_structure_compliance` 与新 Calculator 都依赖该共享模块，各自保留自己的 eligibility、解析语义和 evidence schema。
- 迁移前后用现有 policy structure tests 固定输出；共享文件加入两个 Calculator 的 `source_paths()`，两份 descriptor 都重算 digest。
- 新模块应能把任意可见文本 `[start,end)` 映射为一个或多个原 HTML spans，而不只支持 block。跨标签命中必须保留离散 spans；malformed 时标记精度，不能宣称 EXACT。

## 4. 技术选型与备选方案

### 4.1 推荐：规则/词典 + 可插拔 UIE NER Provider

推荐以轻量规则通道作为确定性高精度通道，以中文通用信息抽取模型作为第二通道。候选模型为 PaddleNLP Taskflow 的 `uie-base`，schema 设为领域标签（例如“涉案人员”“详细地址”“内部批示对象/内容线索”），而不是把所有 PERSON/LOC 作为敏感项。官方文档确认 UIE 支持自定义 schema、返回 start/end 与 probability、可配 `batch_size`、`max_seq_len`、`position_prob`，并提供 nano/micro/mini/medium/base 等尺寸；这使其接口形态适合本任务。[PaddleNLP Taskflow 文档](https://paddlenlp.readthedocs.io/zh/latest/model_zoo/taskflow.html)

限制与上线闸门：

- 当前项目没有 `paddle`/`paddlenlp` 依赖，也没有已配置的模型缓存、离线镜像或 GPU runtime。
- PaddleNLP 源代码仓库声明 Apache-2.0；但截至审计日，不能从该声明推出 UIE 权重、词表与配置也允许再分发。已有官方仓库讨论专门询问此事且尚无答复，因此模型资产许可证记为 **UNKNOWN，阻断生产发布/再分发**。[PaddleNLP 许可证](https://github.com/PaddlePaddle/PaddleNLP)；[权重许可证待确认问题](https://github.com/PaddlePaddle/PaddleNLP/discussions/11252)
- 尚未在本项目 Python 3.12 和目标 CPU/GPU 上安装验证。GPU fp16 的官方文档列出 CUDA、cuDNN 与计算能力要求，但这不等于本项目环境已经满足。
- 零样本 schema 不能证明涉案人员、内部批示等领域标签的 precision/recall；必须以标注集评估，必要时微调。官方 PP-UIE 文档也建议细分场景用少量标注数据定制。[PP-UIE 文档](https://paddlenlp.readthedocs.io/zh/latest/llm/application/information_extraction/README.html)

Provider 应通过项目内部小接口隔离，例如 `infer(batch: list[TextWindow]) -> list[NERSpan]`。Calculator 不在执行中联网下载；模型目录、模型 ID、版本、文件 checksum、runtime/provider 版本均写入参数或部署配置及 diagnostics。Loader 的 `runtime.dependencies` 只能检查模块是否可 import，不能代替模型资产预检。

### 4.2 备选

1. **领域微调 UIE 小模型**：若 `uie-base` 成本过高，可在标注集上比较 `uie-mini/micro/nano`。只有达到分类别验收阈值且许可证明确后才能替换；不能仅凭速度选型。
2. **自建 BERT/ERNIE token-classification 模型**：标签、训练数据和权重许可证完全由项目控制，部署可用 ONNX Runtime；代价是需要标注、训练、导出、token offset 对齐和模型治理。适合中长期生产方案。
3. **远程 NER 服务**：Calculator 只调用受控内部服务。需扩展当前 in-process runtime 的网络、重试、数据出境、审计和幂等约束；现平台没有该能力，首版不推荐。

普通开源中文 NER 仅覆盖 PER/LOC/ORG 时不满足本任务的“涉案人员/内部批示”语义，不能作为完成双通道的依据。

## 6. Calculator 输入与参数契约草案

### 6.1 Descriptor

- key/version：`sensitive_entity_detection@1.0.0`
- execution：`DIRECT`
- input schema：SampleRecord `2.0`
- modality/scope：text / DATASET
- required artifact：`NORMALIZED_DATA`；若外置词典，再增加明确 artifact kind
- deterministic：只有模型、runtime、词典、阈值、硬件确定性策略全部固定时才可标 true；首版建议 false
- sensitive policy：`NORMALIZED_CONTENT`、`emits_raw_content=false`
- resource profile：`HIGH`；memory/timeout 待基准后填写，不编造数值

### 6.2 参数 Schema

建议 `additionalProperties: false`：

```json
{
  "body_roles": ["article.body.html", "article.body.plain"],
  "additional_content_roles": ["article.title"],
  "metadata_paths": [],
  "dictionary_version": "sensitive-elements-1.0.0",
  "model_id": "UNRESOLVED_UNTIL_LICENSE_GATE",
  "model_revision": "IMMUTABLE_REVISION_REQUIRED",
  "model_checksum": "sha256:...",
  "ner_enabled": true,
  "batch_size": 8,
  "window_chars": 384,
  "window_overlap_chars": 64,
  "ner_thresholds": {},
  "evidence_limit": 1000,
  "redaction_mode": "MASKED_CONTEXT",
  "fingerprint_key_id": "deployment-managed-key-id"
}
```

`validate()` 必须验证 schema ref、role/path 非空和唯一、窗口大于重叠、阈值范围、模型与词典资产存在且 checksum 匹配、HMAC key 可用。密钥只来自部署 secret provider，不能进入参数、日志、MetricResult 或 Artifact。

### 6.3 eligible population 与状态

- `input_count`：非空 JSONL 记录数。
- evaluated：至少有一个选定逻辑字段成功完成**规则与 NER 两通道**扫描的 sample。
- excluded：无可扫描文本、记录解析失败、所有字段失败；exclusions 按原因闭合。
- 空文件：`MISSING/NO_INPUT_RECORDS`，无 observations。
- 数据集没有任何选定文本：`NOT_APPLICABLE/NO_ELIGIBLE_TEXT`，无 observations。
- NER 在运行前整体不可用：Stage 应结构化失败并产生 `ERROR`，不得只跑词典后宣称双通道完成。
- NER 运行中部分 batch/窗口失败：`PARTIAL`，成功部分可输出 observations；`semantic_coverage`、`channel_status`、失败窗口数和未扫描字符数必须可见。
- 质量命中不是 Calculator runtime error，也不触发 PASS/FAIL。

## 7. 检测规则设计

### 7.1 正则/词典通道

| 类型 | 候选与校验 | 误报控制 |
|---|---|---|
| `PRC_RESIDENT_ID` | 18 位：行政区前缀、合法生日、顺序码、GB 11643 MOD 11-2 校验码；15 位仅作为可配置 legacy 类型 | 排除全零/显然占位符；必须完整边界；无效校验码仅计 diagnostic，不计命中 |
| `MOBILE_PHONE_CN` | `1[3-9]\d{9}`，允许受控的 `+86/0086` 与空格/短横线归一化 | 左右不得仍是数字；排除模板/掩码/连续重复测试号；固定电话另设类型，不混算 |
| `ADDRESS` | 省市区县、街道/路/巷、门牌/号、楼栋/室等层级词典与有限状态组合 | 需至少达到层级/门牌证据阈值；单独省市地名不命中；机构地址与个人住址可在 evidence 中标 contextual subtype，不直接判违规 |
| `CASE_INVOLVED_PERSON` | 姓名候选 + “犯罪嫌疑人/被告人/被害人/涉案人员/证人”等角色词的句内或受限距离关系 | 普通 PERSON 不命中；公开履职人员、发布机关负责人需负向上下文；规则与 NER 交叉可提高置信 |
| `INTERNAL_INSTRUCTION` | 版本化短语/模板，如内部流转、领导批示、拟办意见、阅示等 + 内容/签名结构 | 单独“批示”“意见”不命中；正文引用公开批示需上下文分类；词典记录 ID、版本、类别和生效状态 |

词典项支持 `exact/token/regex` 类型、正负上下文、作用范围和稳定 rule ID。正则预编译；大词典采用有界多模式匹配。规则版本进入 evidence attributes。严禁在日志打印命中原文。

### 7.2 NER 通道

1. 对 HTML 只在可见文本上推理；script/style/标签属性/URL 不进入 NER。plain/metadata 保持原字符串。
2. 按句界优先切分；超过 `window_chars` 时硬切，窗口重叠 `window_overlap_chars`。保存 `window_start` 的 Unicode code-point offset。
3. batch 只保留有界数量窗口；推理结果先从 token/span offset 回到窗口文本，再加 window start 回到逻辑字段。offset 必须通过 substring 校验。
4. HTML 再通过字符映射回原始 HTML 的一个或多个 spans。实体引用或跨标签可产生离散 spans。
5. 重叠窗口中的同一实体按字段坐标合并；被窗口边缘截断且未在相邻窗口形成完整候选的结果丢弃并计 diagnostic。
6. Provider 输出必须包括模型原标签、归一类别、start/end、probability、model ID/revision；不接受只有文本没有位置的结果。
7. 地址、涉案人员、内部批示采用领域 schema 和上下文后处理。通用 PERSON/LOC 只是候选，不直接进入最终敏感命中。

### 7.3 双通道融合

候选统一为：`sample_id, logical_field, category, start, end, source_spans, channels, rule_ids, model_score, context_flags`。

融合顺序：

1. 校验并归一 offset，去掉无效/越界候选。
2. 同类别、同字段、相同 span：合并 channels，保留规则 ID 与模型分数；只计一次。
3. 同类别、IoU 高或一方完全包含另一方：高精度规则边界优先；否则取经标注集验证的边界策略，不能简单取最长。保留 `merged_from` 但不含原文。
4. 不同类别重叠：身份证优先于泛数字/电话，手机号优先于泛数字；地址与涉案人员可并存，因为语义不同。冲突矩阵版本化。
5. 置信度不把规则布尔值伪装成概率。输出 `confidence_kind=MODEL_PROBABILITY|RULE_VALIDATED|FUSED`；融合分数若无校准集，不对外给单一伪概率。
6. 最终类别计数按融合实体计数；affected document 按 sample 去重；channel diagnostics 可分别统计原始候选，但不得与最终 hit count 混淆。

## 8. Measurement Schema 草案

这些 key 需先加入推荐的 `0202@2.0.0`。所有方向建议 `NEUTRAL`，因为命中是风险线索而非合规裁决。

| key | 类型/单位 | 定义 |
|---|---|---|
| `sensitive_entity_hit_count` | NUMBER/entity | 融合去重后的命中总数 |
| `sensitive_entity_type_counts` | OBJECT | 固定类别到命中数的映射，未知类别禁止静默加入 |
| `affected_record_count` | NUMBER/record | 至少一个最终命中的 sample 数 |
| `evaluated_record_count` | NUMBER/record | 双通道均完成至少一个逻辑字段的 sample 数 |
| `selected_text_count` | NUMBER/content | 实际扫描的逻辑字段数，不把 HTML/plain 重复计数 |
| `scanned_character_count` | NUMBER/code_point | 双通道成功覆盖的逻辑文本 Unicode code points；重叠窗口不重复计数 |
| `eligible_character_count` | NUMBER/code_point | 选定且可扫描的逻辑文本 code points |
| `scan_coverage_ratio` | NUMBER/ratio | scanned / eligible；分母为 0 时结果不可计算，不返回 0 或 1 |
| `channel_status` | OBJECT | rule/dictionary/ner 的 status、版本、成功/失败窗口和覆盖字符，不含异常原文 |

可选的分类统计应放在一个 OBJECT measurement，避免每加一类就破坏 Metric schema。Object 内部仍需独立的版本化 JSON Schema；当前 `MetricMeasurement` 只能声明 OBJECT，不能内嵌结构约束，这是平台现有限制。

不要输出 `safe_record_ratio`、`unsafe_record_count` 或 PASS/FAIL；这些需要后续 Quality Contract 或人工复核规则解释。

## 9. 安全 Evidence Schema 草案

Artifact kind：`SENSITIVE_ENTITY_HITS`；schema ref：`qa-eval://schemas/evidence/sensitive-entity-hits/1.0.0`；JSONL 每行一个融合实体。默认 evidence cap 只限制写出的代表样本，不限制聚合计数。

```json
{
  "sample_id": "stable-id",
  "content_id": "body-html",
  "logical_field": "body",
  "category": "MOBILE_PHONE_CN",
  "channels": ["RULE", "NER"],
  "location": {
    "coordinate_space": "SOURCE_HTML_UNICODE_CODE_POINT",
    "start_inclusive": 120,
    "end_exclusive": 131,
    "source_spans": [{"start": 120, "end": 131}],
    "precision": "EXACT"
  },
  "masked_excerpt": "联系电话：138****5678",
  "value_fingerprint": "hmac-sha256:key-id:...",
  "rule_ids": ["phone.mobile.cn.v1"],
  "model": {"id": "...", "revision": "...", "score": 0.93},
  "review_state": "UNREVIEWED"
}
```

安全约束：

- 不存完整值、完整句子、可逆加密值或裸 SHA-256。短值的裸 hash 可枚举，使用部署密钥 HMAC；仅存 key ID，不存密钥。
- `masked_excerpt` 先按类别掩码实体，再截取小上下文，并对上下文再次运行高风险模式掩码，防止同一句泄露其他实体。内部批示内容默认只留类别、坐标和固定占位符，不留内容片段。
- 日志/exception/diagnostics 只能写 ID、长度、类别、错误码；第三方模型异常也必须清洗。
- `contains_raw_content=false` 仅在自动泄露测试通过后成立。当前 Artifact Store/API 没有字段级访问控制或加密策略，普通 Artifact 不得保存完整敏感值。
- 为 BG-06-04 预留 `sample_id + content_id/logical_field + coordinate_space + spans + mapping_version + entity_fingerprint`。后续去标识化服务应在受控权限下重新读取规范化/原始 Artifact，并校验 fingerprint 后处理；本 Calculator 不返回原文、不修改数据、不执行替换。
- 若未来需要受控原文 Evidence，应新增独立 artifact kind、加密、授权、访问审计与保留期，不能仅把本 schema 的 `contains_raw_content` 改为 true。

## 10. 规模、流式与资源评估

已知规模为 321,902 条、约 8 GB。若 8 GB 按十进制计算，平均约 24.9 KiB/记录；这只是总体均值，不能代表尾部长文本或模型 token 数。

设计要求：

- JSONL 单遍读取；规则与 HTML 映射逐 sample 完成。
- NER 使用 `batch_size × window_chars` 有界窗口队列；批次完成立即融合、聚合、写 Evidence 并释放文本。内存主要由模型权重、runtime workspace、一个 batch 和少量 counters 构成，与记录总数近似无关。
- Evidence 增量写 JSONL；`evidence_limit` 达到后继续扫描和计数，只停止写新的代表行。额外记录 `total_hit_count`、`written_hit_count`、`evidence_capped`。
- 不静默截断长文本。默认完整分块扫描；若运维设置 hard limit，超限部分计入未覆盖字符并使结果 `PARTIAL`。
- 模型只加载一次；禁止每记录加载。首版单进程，避免多 worker 各复制一份模型导致 OOM。并发策略待基准决定。

当前无法给出可信运行时间或内存承诺，因为缺少：字符/token 分布、窗口数、目标 CPU/GPU、模型尺寸、batch、HTML 比例和实际吞吐。实施阶段先运行可复现 benchmark：抽取固定 seed 的分层样本（短/中/p95/p99/最大 HTML），分别测 HTML 映射、规则、CPU NER、目标 GPU NER的 records/s、chars/s、windows/s、峰值 RSS/VRAM；再用 `总窗口数 / 实测 windows/s` 估算全量时间并给出区间。至少做一次 8GB 全量 dry run 才能设置 descriptor 的 timeout/memory。

## 11. 测试设计

### 11.1 单元测试

- 身份证：合法 18 位、X/x、闰日、无效地区/日期/顺序码/校验码、15 位开关、相邻数字。
- 手机号：`+86`、分隔符、边界、掩码、测试号、固定电话、长数字串。
- 地址：完整层级、缺省省市、仅地名、机构名、政策适用地区、门牌、歧义“路/号”。
- 涉案人员：角色+姓名、普通人名、发布机关负责人、引用案例、跨句距离边界。
- 内部批示：模板、公开批示引用、普通“意见/批示”词、签名/日期结构。
- 词典冲突、正负词、版本、重复项、恶意超长规则。
- Unicode offset：中文、emoji、组合字符、HTML entity；明确 code point 而非 byte。
- HTML 跨标签实体、实体引用、script/style、malformed HTML、离散 source spans。
- 窗口边界、重叠去重、token offset 回映射、被截断候选。
- 同一原始 content 的 HTML/plain 去重；同文跨真实字段不误合并。
- 融合冲突矩阵、同 span 双通道只计一次、Evidence cap 不影响统计。
- 所有 evidence/log/diagnostic/exception fixture 扫描，断言不存在完整身份证、手机号和种子 secret。

### 11.2 模型与数据集

- 只使用授权的脱敏真实格式样本和明确标记的合成样本；保留来源、授权和生成规则。
- 按类别、字段类型、长度、HTML/plain、正/负/困难负例分层。
- 单独标注普通 PERSON/LOC、公开联系人、机构地址、政策适用地区、公开批示等误报集合。
- 双人标注与仲裁；计算分类别 precision/recall/F1、span exact/overlap、文档级误报率。阈值由评审设定，不能在无基线时虚构。
- 模型版本/词典/规则更新必须重跑冻结集，输出差异报告。

### 11.3 平台与端到端

- 参数 schema 与 runtime `validate()` 一致，未知参数拒绝。
- 无输入、无合格 role、null/missing、wrong modality、坏 JSON、部分 batch 失败、模型缺失/checksum 不符。
- Registry sync、Binding measurement、0202 版本并存、Applicability、Logical/Physical Plan、Loader digest。
- `DatasetVersion -> DIRECT Stage -> MetricResult -> Evidence Artifact`；MetricResult 非 OK 时无 observations，population 闭合。
- Evidence schema 校验、Artifact record_count/checksum、API 返回不泄露原文。
- 共享 HTML 模块迁移后 policy structure 全量回归；两个 descriptor digest 均正确。
- 大量记录的有界内存测试和目标环境 benchmark。

## 12. 风险及解决方案

| 风险 | 影响 | 解决方案/闸门 |
|---|---|---|
| 0202 measurement 不兼容 | Registry/Contract 不合法或语义造假 | 新增 0202 v2，旧版本并存；显式 produced measurements |
| 模型权重许可证未知 | 无法合法再分发/上线 | 法务/模型提供方书面确认；否则训练自有权重或换明确许可模型 |
| Python 3.12/硬件未验证 | Loader 可 import 但运行失败 | 独立 extra/镜像锁版本，在目标环境做安装、加载、推理 smoke test |
| 通用 NER 标签不覆盖领域语义 | 涉案人员/批示漏报或普通人地名误报 | 自定义 schema + 领域标注评估/微调 + 上下文门控 |
| HTML/plain 重复 | 计数翻倍 | 逻辑槽位与同源表示优先级，不扫描两份正文 |
| HTML 位置错误 | BG-06-04 错误替换 | 共享字符级 source map、离散 spans、substring/fingerprint 校验、精度标记 |
| Evidence 泄露 | 二次安全事件 | HMAC、类别掩码、二次上下文清洗、日志清洗、泄露测试、普通 Artifact 禁原文 |
| Evidence cap 影响统计 | 指标低估 | cap 只控制落盘，聚合始终全量 |
| 模型不可用时退化为单通道 | 虚假“双通道完成” | 全局不可用 ERROR；局部失败 PARTIAL + 覆盖率/通道状态 |
| 平均规模掩盖长尾 | OOM/超时 | 分层 profile、完整分块、有界 batch、全量 dry run 后设资源值 |
| 模型/词典漂移 | 结果不可复现 | immutable revision/checksum、规则/词典版本、结果记录 runtime identity |
| Artifact 服务信任 redaction 声明 | 标记 false 但内容仍泄露 | Calculator 内强制安全 schema + 测试；中期增加平台内容扫描/访问控制 |

## 14. 可执行验收标准

以下条件全部满足才可称为 BG-06-01 双通道完成：

1. 0202 新版本合法声明全部输出，旧 0202 与旧 Binding 行为不变；Registry sync 和 Contract/Planner 测试通过。
2. Loader 在目标环境验证 entrypoint、依赖与最终 code digest；模型、词典另有 immutable revision/checksum 预检。
3. 对每个 eligible 逻辑字段，规则/词典与 NER 均实际运行；全局 NER 不可用返回 ERROR，局部失败返回 PARTIAL 且覆盖率准确。
4. 身份证校验、手机号边界、地址层级、涉案上下文、内部批示上下文均有正例、困难负例和边界测试。
5. 普通人名、普通地名不自动计为最终敏感命中；融合后同一实体不因双通道、重叠窗口或 HTML/plain 重复而重复计数。
6. HTML 命中的 source spans 可回验；坐标明确为 Unicode code point `[start,end)`，跨标签保留离散 spans，不能冒充 byte offset。
7. Evidence 默认不含完整敏感值；对 Artifact、MetricResult、API payload、日志、diagnostics 和异常执行自动泄露扫描并通过。
8. Evidence cap 不改变总命中数、分类统计、受影响记录数和覆盖率；population 与 exclusion 严格闭合。
9. 标注冻结集报告分类别 precision/recall/F1 和文档级误报；达到由业务/安全评审预先批准的阈值。没有阈值或数据集不得宣称准确可用。
10. 在目标部署环境完成分层 benchmark 和 321,902 条/约 8GB 全量 dry run，记录总窗口、吞吐、峰值 RSS/VRAM、运行时间、错误/重试和覆盖率；descriptor 资源参数以实测为准。
11. 输出仅为风险线索测量，不包含质量评分、合规 PASS/FAIL，不修改原始数据，不执行 BG-06-04 去标识化。
