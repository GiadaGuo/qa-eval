# policy.jhsjk_article 指标实现设计（Stage 1.2）

## 1. 文档范围

本文以 `references/guide-metrics.yaml` 中的数据质量维度为指南来源，结合仓库级 ADR-0001、`plan/v0/pm-v0.md`、`plan/v0/rd-v0.md`、当前 `SampleRecord`、`FieldMappingConfig` 和 `MySQLRecordAdapter`，为 `policy.jhsjk_article` 设计 0201–0208 及其模态子指标到 Calculator 的映射。本文只描述计算语义与证据需求，不设置质量阈值、不实现 Calculator、不产生 Metric Result。0101–0104 和 0301–0305 不属于本文范围。

适用性状态仅表示指标是否适合该数据集：

- `APPLICABLE`：指标语义适用于文章数据；不代表现有输入和实现已足够。
- `NOT_APPLICABLE`：按当前已知的数据模态或标注情况不适用。
- `NEEDS_CONFIRMATION`：必须补充业务口径、说明文档或外部证据后才能确定。

计算方式分类：`直接计算`、`人工证据`、`模型辅助`、`无法判断`。模型辅助结果必须保留模型、Prompt/Rubric、版本和抽样复核证据，不得作为未经验证的客观事实。

## 2. 已知数据边界与字段投影

- 样本粒度：一篇文章一条 `SampleRecord`。
- 标识：源字段 `id` → `sample_id`；`article_id` 只是站点文章编号。
- 核心文本：`content`（HTML）与 `plain_text_content`（纯文本）→ `data_content[]`，角色保留源字段名。
- 元数据建议映射：`article_id`、`title`、`url`、`pub_date`、`origin_name`、`summary` → `metadata`。
- 时间建议映射：`create_time` → `timestamps`。`pub_date` 当前前端建议放在 `metadata`，计算时仍需解析为业务日期。
- 来源与血缘：`source.source_uri`、`source.source_record_id`、`lineage.adapter_id/version/input_fingerprint`。
- 当前适配器将核心字段的源 `NULL` 转为 `""`。因此需要区分 NULL 与空字符串的指标，应读取固定原始快照、reject/转换统计或新增不丢失缺失语义的标准化证据；本文不修改适配器。
- 当前已知映射没有 annotation/label 字段，`SampleRecord.annotations` 为空。
- 本设计不把 HTML 内的图片 URL 当作已接入的图像样本，也不下载外部媒体。

| 适用性 | 数量 | 编码 |
|---|---:|---|
| APPLICABLE | 13 | 0201、0202、0204、0205、0206、0208、02080101—02080107 |

## 4. 逐项设计

### 0201 格式规范性 — APPLICABLE

- 判断依据与方式：每条文章记录应满足源 Schema、字段映射、SampleRecord Schema 和可直接处理的文本格式；可“直接计算”。格式合规不等同于内容优质。
- 输入/外部证据：固定原始快照、MySQL Schema、`FieldMappingConfig`、适配成功/失败记录、`SampleRecord`、HTML 解析结果；至少涉及 `id`、`content`、`plain_text_content` 及已确认映射字段。
- 建议 Calculator：`article_format_conformance_ratio`，内部产生字段存在、类型、编码、时间可解析、HTML 可解析、SampleRecord 校验等确定性检查。
- 计算方法：先对每条记录执行经版本化的格式规则；只有全部必需规则通过才计入 A。A=格式符合预定标准的记录数，B=固定快照总记录数；`X=A/B`。适配失败记录必须进入 B 并保留原因；基础设施读取失败则整体 `ERROR`，不能当作不合规记录。
- 参数：必需字段集合、允许的 MySQL/标准化类型、字符编码、日期解析格式、HTML 解析模式、空值是否为格式错误。参数必须来自 Schema/格式规范，不是业务质量阈值。
- 证据输出：A/B、规则版本、各失败原因计数、失败 `sample_id`/源行定位、字段名、脱敏值摘要、适配器版本和输入指纹。
- 优先级与覆盖：P0。可覆盖指南“符合预定标准、可直接使用”的结构与解析层语义；是否真正“可直接用于模型训练”仍依赖目标任务转换，故为部分覆盖。

### 0202 安全规范性 — APPLICABLE

- 判断依据与方式：文本文章可能包含指南所述非法或有害内容；需要“模型辅助 + 规则扫描 + 人工复核”，仅关键词不能完整代表安全规范性。
- 输入/外部证据：`title`、`summary`、`plain_text_content`，必要时 HTML 去标签文本；适用法律/安全分类规范和人工标注样本。
- 建议 Calculator：`text_safety_review_ratio`（分类模型/规则召回、人工复核闭环）。
- 计算方法：A=按已批准安全规范判定为符合要求的记录数，B=成功进入安全评测的记录总数；`X=A/B`。模型不确定或审核缺失应标记 UNKNOWN，不擅自放入 A。
- 参数：安全分类体系、模型与版本、Prompt/Rubric、置信度分流规则、脱敏策略；不设置合格阈值。
- 证据输出：分类标签、置信度、命中规则、脱敏片段、模型版本、复核结论和 A/B。
- 优先级与覆盖：P2；混合审核可较完整覆盖，纯规则或单模型仅部分覆盖。

### 0203 标注规范性 — NOT_APPLICABLE

- 判断依据与方式：当前文章字段与映射中没有标注字段，`SampleRecord.annotations` 为空；指南明确无标注场景不适用；归类为“无法判断/当前不计算”。若后续确认存在人工标签，应重新评估。
- 输入/外部证据：标注任务声明、标注字段映射、标注规范和流程记录。
- 建议 Calculator：当前无；有标注后可用 `annotation_schema_conformance_ratio`。
- 计算方法：当前不计算 A/B，输出 NOT_APPLICABLE；不得用空 annotations 计算为 0。
- 参数：无；未来需要标注 Schema 和规则版本。
- 证据输出：无标注字段的映射快照、适用性决定及审核记录。
- 优先级与覆盖：N/A；当前不覆盖。

### 0204 结构完整性 — APPLICABLE

- 判断依据与方式：文章记录包含多个预期结构字段，可做“直接计算”；“合理缺失范围”是业务规则，尚未确认，因此 Calculator 只能先输出字段级缺失事实和按确认规则计算的记录级比例。
- 输入/外部证据：固定原始快照（首选）、源 Schema 的 nullable 信息、字段映射、reject 记录、标准化 SampleRecord；候选字段为 `id/article_id/title/url/pub_date/origin_name/summary/content/plain_text_content/create_time`。
- 建议 Calculator：`article_structure_completeness_ratio` + 可复用特征 `field_missing_flags`。
- 计算方法：对每条记录分别保留 `NULL`、空字符串、纯空白、字段缺失和解析失败。由经确认的“必需字段 + 允许缺失规则”判定该记录是否满足合理范围。A=满足规则的记录数，B=固定快照总记录数；`X=A/B`。同时输出每字段各类缺失率。不能只读当前标准化核心内容，因为适配器会把核心 NULL 转为空字符串。
- 参数：必需/可选字段集合、NULL/空字符串/纯空白定义、条件必填规则、是否将转换失败计为不完整。参数不包含最终合格阈值。
- 证据输出：A/B、逐字段 NULL/空/空白/缺列计数、记录级失败字段、`sample_id`/源定位、规则版本、输入指纹、转换失败原因。
- 优先级与覆盖：P0。规则确认后可完整覆盖指南比例语义；规则未确认时只提供缺失画像，属于部分覆盖，不能宣称指南得分。

### 0205 内容真实性 — APPLICABLE

- 判断依据与方式：文章具有 `url`、`origin_name`、`article_id` 和来源血缘，可验证可追溯性；但与源站内容一致、生成过程及真实分布不能只靠表内字段证明；“直接计算 + 人工证据”。
- 输入/外部证据：上述元数据、快照/Manifest/指纹、采集日志、来源许可，必要时经授权的源站归档或校验记录。
- 建议 Calculator：`article_traceability_ratio` 与独立的人工/外部 `source_consistency_review`。
- 计算方法：A=同时满足经确认的来源标识、URL 合法性、血缘完整性及源一致性证据要求的记录数，B=记录总数；`X=A/B`。若只验证可追溯字段，应以代理结果发布，不得等同完整真实性。
- 参数：来源必需字段、URL 规则、允许来源列表、外部核验策略、生成数据声明。
- 证据输出：来源字段、血缘指纹、URL 检查、外部证据引用、差异摘要、A/B。
- 优先级与覆盖：P1；仅表内检查为部分覆盖，加入可靠源一致性证据后才可接近完整覆盖。

### 0206 内容一致性 — APPLICABLE

- 判断依据与方式：同一文章的 `title`、`summary`、HTML 正文与纯文本正文应语义匹配；“直接计算 + 模型辅助”。
- 输入/外部证据：四类文本角色、HTML 去标签结果、经人工确认的一致性 Rubric 和校准样本。
- 建议 Calculator：`article_cross_field_consistency_ratio`（HTML/纯文本确定性对齐 + embedding/NLI/LLM 辅助 title-summary-body 语义核验）。
- 计算方法：A=按已确认组合规则判为一致的记录数，B=可评测记录数；`X=A/B`。各子检查单独输出；缺字段记录交由 0204，不可静默排除，分母策略须记录。
- 参数：字段组合、HTML 规范化、相似度算法、模型/Rubric、UNKNOWN 处理；不设置达标阈值。
- 证据输出：字段对、确定性差异摘要、模型分数/结论、脱敏片段、模型版本、人工复核、A/B。
- 优先级与覆盖：P1；HTML/纯文本对齐只覆盖局部，完整语义一致性需要模型与人工校准。

### 0207 类型一致性 — NEEDS_CONFIRMATION

- 判断依据与方式：必须先确认该数据集属于通识、行业通识还是行业专识，以及对应知识边界；当前只有文章来源示例；“模型辅助 + 人工证据”。
- 输入/外部证据：数据集类型声明、领域分类体系、目标内容范围、代表性人工标注集、正文文本。
- 建议 Calculator：`dataset_type_conformance_ratio`。
- 计算方法：确认类型后，A=符合该类型内容要求的记录数，B=经评测记录总数；`X=A/B`。类型未确认前不计算。
- 参数：类型与领域 taxonomy、模型/Rubric、抽样与复核方案。
- 证据输出：类型声明、分类结果、置信度、脱敏片段、复核记录、A/B。
- 优先级与覆盖：P2；未确认类型时无法覆盖，确认并校准后可部分到完整覆盖。

### 0208 内容干净性 — APPLICABLE

- 判断依据与方式：文本模态适用，但它是父指标；指南没有给出七个文本子指标如何汇总为“内容干净”。归类为“无法直接判断”，不得用任一子指标冒充父指标。
- 输入/外部证据：02080101—02080107 的独立结果、父指标记录级判定规则、子指标缺失/错误状态。
- 建议 Calculator：`text_cleanliness_composite_ratio`，仅在业务确认组合语义后实现。
- 计算方法：确认组合规则后，A=按父指标规则判为内容干净的记录数，B=进入父指标判定的记录总数；`X=A/B`。不能直接平均七个数据集级值，也不能把“纯净程度”02080106当作0208。
- 参数：子指标组合逻辑、记录级判定语义、UNKNOWN/ERROR 传播、适用子指标集合；不设置业务阈值。
- 证据输出：A/B、每条记录各子指标状态、组合规则版本、排除/未知原因、子结果引用。
- 优先级与覆盖：P2；组合口径确认前只有子指标覆盖，父指标为未实现。

### 02080101 文本困惑程度（PPL） — APPLICABLE

- 判断依据与方式：纯文本正文适用；需要“模型辅助”（确定版本语言模型的确定性推理）。
- 输入/外部证据：`plain_text_content`，可选 `title/summary`；语言识别结果。
- 建议 Calculator：`text_perplexity`。
- 计算方法：按固定 tokenizer/语言模型计算每条文本 token 级负对数似然和 PPL，输出分布；指南未给 A/B 公式，不构造合格记录比例。
- 参数：字段角色、模型/tokenizer 及版本、最大长度与分块/聚合方式、语言路由。
- 证据输出：样本 PPL、token 数、分块值、模型版本、截断状态、分布摘要。
- 优先级与覆盖：P2；对模型覆盖语言和长度范围内部分至较完整覆盖。

### 02080102 知识信息密度 — APPLICABLE

- 判断依据与方式：文章正文适用，但“有效知识信息”没有操作定义；“模型辅助 + 人工校准”。
- 输入/外部证据：`title/summary/plain_text_content`、领域/任务定义、Rubric、人工标注校准集。
- 建议 Calculator：`knowledge_information_density`。
- 计算方法：按确认后的信息单元、事实陈述或有效 token 口径计算密度；口径确认前只输出候选特征，不输出指南指标值，无既定 A/B。
- 参数：信息单元定义、字段、模型/Rubric、分块和聚合方式。
- 证据输出：信息单元计数/分数、文本长度、脱敏依据片段、模型和复核记录。
- 优先级与覆盖：P2；未确认口径时无法覆盖，代理特征不得冒充完整指标。

### 02080103 重复内容程度 — APPLICABLE

- 判断依据与方式：文章可能存在跨文档、段落、句子重复，适合“直接计算”；语义近重复可后续模型辅助。该子指标不等同于父指标0208。
- 输入/外部证据：以 `plain_text_content` 为主，辅以 `title/summary`；`sample_id`、`article_id`、URL 用于定位，不能未经验证作为唯一去重键。
- 建议 Calculator：`text_duplicate_degree`，分为 exact、normalized、near-duplicate、within-document 四类特征。
- 计算方法：固定规范化后计算全文哈希识别完全重复；用段落/句子哈希识别片段重复；用 MinHash/SimHash 或 embedding 候选召回近重复。输出重复组、受影响记录数、重复对数量和重复覆盖比例。指南未定义唯一 A/B，若需记录级比例，建议候选口径为 A=无重复命中的记录数、B=记录总数，但必须先确认“程度”是重复率还是干净率及重复组代表记录如何处理。
- 参数：文本字段、Unicode/空白/HTML规范化、句段切分、n-gram、候选算法、相似度判定参数、组代表策略；所有参数版本化，不在本阶段给数值。
- 证据输出：重复组 ID、样本对、重复类型、相似度、重叠片段哈希/脱敏摘要、组大小、受影响记录计数、算法版本。
- 优先级与覆盖：P0。完全/规范化重复可确定性完整覆盖对应语义；近重复取决于召回与确认规则，整体为部分覆盖，校准后提升。

### 02080104 文本完整程度 — APPLICABLE

- 判断依据与方式：纯文本可能过短、截断或正文不完整；可“直接计算 + 模型辅助”。不能把字段缺失（0204/02080105）全部等同于文本不完整。
- 输入/外部证据：`title/summary/plain_text_content/content`、HTML 结束结构、长度/句段统计、采集/截断日志；必要时人工校准样本。
- 建议 Calculator：`text_completeness_degree`。
- 计算方法：输出字符/token/句段长度、结尾标点/结构、HTML与纯文本尾部对齐、异常截断信号。若需指南记录比例，A=按经确认完整性规则判为完整的记录数，B=可评测记录总数；`X=A/B`。最小长度和截断判据属于待确认参数，不在此设定。
- 参数：评测字段、长度统计单位、语言切句、HTML解析、完整性规则、模型/Rubric（若启用）、UNKNOWN处理。
- 证据输出：长度与结构特征、触发规则、尾部脱敏片段、HTML/纯文本差异、模型结论、A/B。
- 优先级与覆盖：P0。确定性异常信号只能部分覆盖；结合经校准模型/人工规则可提高语义覆盖。

### 02080105 信息缺失程度 — APPLICABLE

- 判断依据与方式：文章明确包含标题、摘要、正文、段落等结构；可“直接计算”。它关注关键结构要素，和0204的通用字段完整性相关但不等同。
- 输入/外部证据：`title/summary/content/plain_text_content`、HTML结构、数据集文章模板说明。
- 建议 Calculator：`article_key_element_missing_degree`。
- 计算方法：逐条输出关键要素缺失标记及缺失要素数；指南未给子指标 A/B，若转记录比例须先确认关键要素集合与组合规则。
- 参数：必需结构要素、空值定义、HTML标题/段落识别、条件适用规则。
- 证据输出：缺失要素列表、字段/DOM定位、样本定位、分布汇总。
- 优先级与覆盖：P1；结构规则确认后较完整覆盖，当前为部分覆盖。

### 02080106 文本纯净程度 — APPLICABLE

- 判断依据与方式：HTML和纯文本可能含广告、页码、特殊符号、乱码等干扰；适合“直接计算”，广告语义识别可模型辅助。该指标不是父指标0208。
- 输入/外部证据：`plain_text_content`、`content`、`title/summary`，字符编码信息，文章模板/广告规则。
- 建议 Calculator：`text_purity_degree`，输出干扰类型特征与记录级候选结论。

## 5. 首批建议实现

首批建议实现以下五项，它们可复用现有字段映射并优先产生确定性、可追溯事实：

1. `0201 格式规范性`：先固化 Schema、适配/reject 和解析证据。
2. `0204 结构完整性`：先输出 NULL/空/空白/缺列事实，再等待必需字段规则确认。
3. `02080103 重复内容程度`：先做全文/规范化哈希及句段重复，再扩展近重复。
4. `02080104 文本完整程度`：先输出长度、句段、尾部和HTML对齐异常信号。
5. `02080106 文本纯净程度`：先做乱码、控制字符、HTML残留和模板噪声特征。

## 6. 尚待确认的口径

1. `jhsjk_article` 的正式字段映射、真实 DDL、nullable、字符集、时区以及固定快照方案。
2. 0201 的预定格式规范、必需字段及 HTML 合法性标准。
3. 0204 的必需/可选字段、合理缺失范围，以及 NULL、空字符串、纯空白和转换失败的处理。
4. 02080103 的“程度”输出方向、近重复定义、相似判定参数和重复组代表记录策略。
5. 02080104 的过短/异常截断判据及正文完整性 Rubric。
6. 02080105 的关键结构要素集合。
7. 02080106 的允许符号、乱码/广告/页码/模板噪声规则及组合语义。
8. 0208 如何由适用的文本子指标形成记录级“内容干净”结论；确认前不得汇总父指标。
9. 数据集是否确无标注；若存在标签，需要重评 0203。
10. 数据集类型及领域边界，用于 0207。
