## 根因：功能完全缺失，非故障（有代码证据）

- apps/api/routes/datasets.py 仅有 POST/GET/GET 三个端点，dataset_versions.py 仅有创建/上传/字段映射/发布/查询，全仓库 grep 无任何 DELETE 路由。
- DatasetService、DatasetVersionService 无删除方法；DatasetRepository / DatasetVersionRepository 端口无 delete 抽象——即领域层到 ORM 层整条链路都不存在删除能力。
- 前端 DatasetListPage 操作区只有「查看版本」，DatasetDetailPage 版本表只有「详情/上传/字段映射/发布」；api/datasetVersions.ts 无 delete 函数。

## 数据库真实关联（以 ORM 外键为准）

引用 dataset_versions.id 的 7 张表全部 ondelete=RESTRICT：

| 引用表 | 定性 |
|---|---|
| physical_evaluation_plans / evaluation_runs / metric_results / quality_reports / quality_contract_versions | 下游评测依赖，受保护 |
| dataset_manifests / dataset_profiles | 版本内部附属数据 |

dataset_versions.dataset_id → datasets.id 同为 RESTRICT。无需任何数据库变更，现有约束恰好构成并发兜底。

## 删除策略

- 版本可删：5 张下游表引用数均为 0；manifest + profile 视为版本附属，同一事务内先删附属再删版本行。
- 版本不可删：任一下游依赖 > 0 → 409 DATASET_VERSION_IN_USE，零删除（依赖检查先于任何 DELETE）。
- 数据集可删：全部版本无下游依赖（或无版本）→ 删全部版本（含附属）+ 数据集行；否则 409 DATASET_IN_USE，dependencies 聚合各依赖总数并附 protected_versions 计数。
- 未引入软删除、未改任何外键、未开启 CASCADE；历史评测结果可追溯性不受影响。
- 并发窗口（检查后、删除前新增引用）由 RESTRICT 兜底：IntegrityError 被捕获 → 事务回滚 → warning 日志 → 转 409，不泄漏 500。

1. Artifact Store 文件未清理：删除只清 DB 行，datasets/{dataset_id}/{version_id}/ 下产物文件保留（ArtifactStore 端口无 delete 能力）；建议后续做基于指纹引用计数的离线 GC。
